# PR 审查 Skill 迁移计划

## 最终目标

用户通过 `$ai-pr-review <GitHub PR URL>` 或明确的 PR 审查请求，获取中文审查结果：改动摘要、有依据的问题、具体位置、触发条件、影响、修复建议、验证情况和审查限制。

## 设计

- 仓库内维护 `skills/ai-pr-review/`，并安装一份到本机用户 skill 目录，便于在其他项目调用。
- `SKILL.md` 负责范围识别、取数、按需查证、结论质量和输出；`references/` 保存详细审查规范。
- Python 标准库脚本负责只读 GitHub API 请求、分页、固定提交版本、获取文件和报告覆盖情况。身份凭据使用现有环境变量或 GitHub CLI 登录态；公开 PR 可以匿名读取。
- AI 使用实际 diff、相关文件与必要验证判断变更正确性。缺少数据、权限或验证环境时明确说明，不生成模拟成功结果。
- 默认在对话中输出 Markdown；用户请求 HTML 时基于已核实结论导出报告。
- 第一版仅处理单个 github.com PR；不增加批量审查、自动修复、评论发布或合并流程。
- Chrome 扩展与后端保留为已有使用方式，不作为 skill 的运行依赖。

## 实施步骤

1. 核实 PR 元数据、文件分页、固定 SHA 获取内容和 fork PR 的读取规则。
2. 实现自包含 skill 与数据脚本；数据保存在独立输出目录，避免改变被审查项目。
3. 将 README 的主要入口改为 skill，说明运行依赖、安装和调用方法。
4. 运行 skill 结构校验，以及针对分页、错误处理、提交变化、文件内容等关键行为的最小验证；不引入测试框架。
5. 用真实公开 PR 获取数据、读取相关代码并完成一次中文审查，保留验收记录；若环境限制阻断某项，准确记录。
6. 安装到本机，核对安装副本，检查最终差异并更新日志。

## 完成标准

- Skill 能脱离项目后端独立运行，随包脚本和参考文件均可定位。
- 完整遍历文件分页；记录 base/head SHA；检测获取期间版本变化；数据不全有明确标记。
- 能按固定提交读取 head/base 文件，正确处理 fork 与重命名；错误不能包装为成功。
- 报告中的每个问题有真实位置与可说明的影响路径；允许没有问题，区分静态审查、实际验证和未知项。
- 至少一条真实公开 PR 流程验证通过，并留下可检查的记录。
- 本机安装与仓库版本一致，提供用户可以直接复制的调用示例。

## 风险与验收边界

- 私有仓库需要用户已有的 GitHub 访问权限；匿名请求可能受速率限制。
- GitHub patch 可能缺失或不完整。需要时读取完整文件、对应提交或在独立目录获取 Git 历史；不得把未读代码视为已审查。
- 静态审查不能证明所有运行场景正确。报告须明确哪些运行验证实际执行，不能声称绝对可用。
